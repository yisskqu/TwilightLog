## 0. 一页总览

### 0.1 产品是什么

TwilightLog 是一个同时承载文章和摄影作品的个人内容网站：

- **文章**：专栏 → 文章列表 → 文章详情，支持图片、代码块、公式、Mermaid、目录定位。
- **摄影**：摄影专栏 → 相册 → 照片瀑布流 → 照片详情弹窗，兼容横竖和不同画幅。
- **内容生产**：编辑维护本人内容，所有新增和修改经管理员审批后公开；管理员可直接发布和管理全站。
- **访客**：匿名浏览，不需要注册、收藏或登录。

### 0.2 技术基线

```text
后端：Go + PostgreSQL
公开站：Astro 静态生成 + React islands
管理后台：React + Vite + Ant Design
图片：阿里云 OSS + 阿里云函数计算 FC
部署：Caddy + Docker Compose
```

关键约束：

- 当前服务器 2 核 2G / 40G ESSD，图片必须外置，构建不在服务器执行。
- 当前不购买 CDN，但代码和资源 URL 必须预留 CDN 接入。
- 域名 `twilightlog.com` / `www.twilightlog.com` 已备案；公开站 canonical 用 `www`，主域 301。
- 开发者非 Web 行业，主要借助 AI 实现；方案优先选择生态成熟、AI 易生成、易排错的技术。
- 长期维护，功能模块要能独立上下线；采用模块化单体，不做微服务。

### 0.3 开发顺序

```text
阶段 0  账号、域名、服务器、对象存储准备
阶段 1  仓库、骨架、数据库、部署底座
阶段 2  认证、角色、权限、路由防护
阶段 3  媒体上传、EXIF、衍生图、水印
阶段 4  内容模型、只读 API、搜索、种子数据
阶段 5  公开站静态 MVP（首页/文章/摄影）
阶段 6  管理后台与编辑工作区（审批/推荐/回收站）
阶段 7  联调、测试、性能与安全验收
阶段 8  上线、备份、监控、回滚
阶段 9  上线后迭代（CDN/腾讯云/评论/多端）
```

### 0.4 交付物

- 可访问的公开站：首页、文章、摄影、详情、搜索筛选、深浅色、多端适配。
- 管理后台：内容管理、审批中心、推荐配置、账号权限、回收站、通知、审计。
- 编辑工作区：本人内容、草稿、提交审核、撤回、下线、回收站、审核记录。
- Go API、PostgreSQL 数据库、OpenAPI 契约、部署脚本、备份脚本。
- 技术文档、PRD、本方案、运维手册。

## 1. 产品需求

### 1.1 目标与非目标

**目标：**

1. 访客能通过搜索、多标签、日期、排序和分页发现内容。
2. 文章完整呈现文字、图片、代码、公式、Mermaid 和目录。
3. 摄影以瀑布流和大图弹窗呈现，兼容任意比例。
4. 编辑只能维护本人内容，修改必须审批，公开旧版不被待审版覆盖。
5. 管理员能审批、管理全站、配置首页推荐、管理账号和回收站。
6. PC、平板、手机可用；深浅色主题可保存；照片不被原图泄露。

**首版非目标：**

- 不做评论、点赞、收藏、订阅、分享功能。
- 不做编辑协作、所有权转让、多人共同拥有。
- 不做管理员在后台新增管理员；管理员账号只由服务器命令创建。
- 不做公开注册、找回密码、验证码登录。
- 不做小程序和 Android 客户端。

### 1.2 角色与权限

| 角色 | 定义 | 核心能力 |
|---|---|---|
| 访客 | 未登录，或已登录但无编辑权限 | 浏览公开内容、切换主题 |
| 编辑 | 管理员授权并登录 | 管理本人专栏、文章、相册、照片；提交审核；下线/回收站 |
| 管理员 | 服务器命令添加的账号 | 全站内容、审批、账号权限、首页推荐、回收站、系统管理 |

权限要点：

- 前端隐藏入口不算权限控制；所有对象级权限在 API 校验。
- 编辑不能查看、修改、下线他人内容；不能选择他人专栏/相册作为上级。
- 管理员代编辑操作不改变内容所有者，但记录实际操作管理员。
- 撤权后，编辑按访客处理；已公开内容所有者转给管理员，待审内容由管理员接管。
- 永久删除、创建账号、授权/撤权、重置密码、禁用/启用、直接发布他人内容、审批替换公开版、标签合并/重命名/停用，仅 PC 提供。
- 首次发布（当前无公开版本）的审批通过在手机端可用，且只支持单条。
- 账号字段为用户名（唯一）、邮箱（唯一）、角色、状态；普通账号由管理员在后台创建，管理员账号只由服务器命令创建。

### 1.4 内容对象

| 对象 | 关键字段 |
|---|---|
| 文章专栏 | 所有者、名称、简介、封面、主题标签、创建/更新时间、公开状态 |
| 文章 | 所有者、标题、所属专栏、摘要、标签、发布时间、更新时间、正文、公开状态 |
| 摄影专栏 | 所有者、名称、简介、封面、题材、标签、创建/更新时间、公开状态 |
| 相册 | 所有者、所属摄影专栏、标题、简介、封面、标签、创建/最新更新时间、主要位置、公开状态 |
| 照片 | 所有者、所属相册、原图、衍生图、标题、描述、标签、上传/拍摄时间、展示元数据、位置、公开状态 |

| 账号权限记录 | 账号、角色变化、操作管理员、时间 |

### 1.5 版本与状态

同一内容可以同时存在：

- **公开版本**：最近一次审批通过或管理员直接发布，且当前允许公开的版本。
- **工作版本**：正在编辑的草稿、待审核或已驳回版本。

文章专栏、摄影专栏、文章、相册、照片均适用同一规则：编辑提交后公开端仍显示原公开版本，管理员审批通过后才更新。

规则：

1. 编辑每次新增或修改都形成工作版本，不直接改变公开版本。
2. 待审版本锁定；要改先撤回。
3. 审核期间公开端继续显示旧版；驳回不影响旧版。
4. 管理员直接发布可立即更新公开版，但记录操作人和时间。
5. 只有审批通过才更新公开端的更新时间。

公开状态：

| 状态 | 公开端 |
|---|---|
| 草稿 | 不展示 |
| 已发布 | 上级也公开时展示 |
| 已下线 | 不展示 |
| 回收站 | 不展示 |

审核状态：

| 状态 | 含义 |
|---|---|
| 无待审版本 | 可新建修改并提交 |
| 待审核 | 工作版本已提交并锁定 |
| 已驳回 | 查看理由、修改、重新提交 |

公开可见条件：

1. 公开状态为“已发布”。
2. 当前公开版本已审批通过或管理员直接发布。
3. 所有上级均公开可见。
4. 不在回收站。
5. 图片衍生版本已生成且可公开。
6. 相册至少有一张公开照片。

### 1.6 核心流程

**访客：**

```text
首页 → 文章/摄影 → 列表（搜索/标签/日期/排序/分页）→ 详情
```

**编辑：**

```text
登录 → 新建/修改本人内容 → 保存草稿 → 提交审核
  ├─ 通过 → 形成公开版本
  ├─ 驳回 → 查看理由 → 修改 → 重新提交
  └─ 撤回 → 继续编辑
```

**管理员：**

```text
登录 → 审批（完整预览/差异）→ 通过或驳回
     → 内容管理 → 推荐配置 → 账号权限 → 回收站 → 审计
```

### 1.7 公开端功能

#### 首页

- 顶部：站点标识、首页/文章/摄影导航、登录入口、主题切换。
- 首屏：网站介绍、文章和摄影主入口。
- 推荐文章区 `N₁`、推荐相册区 `N₂`，由管理员分别配置。
- 先展示管理员手动推荐并按顺序；不足时按更新时间从新到旧补位；去重。
- 推荐项失效立即移除并补位；`N=0` 隐藏对应区域。
- 推荐卡片进入视口淡入上移；遵循 `prefers-reduced-motion`。

#### 列表通用规则

- 搜索：点击或 Enter 触发；去首尾空格；中文包含匹配，英文忽略大小写。
- 多标签：同一列表多选时逻辑 `AND`，必须同时包含全部已选标签。
- 标签作用域隔离：文章标签和摄影标签两套词库，不混用；摄影“题材”是独立枚举。
- 日期：不同列表用不同字段；下界按列表取当前公开内容的最早对应时间（照片取最早拍摄日期，不受专栏创建日期限制）；起止可单填；结束不晚于今天；起止颠倒不执行。
- 排序：立即生效；相同值按标题稳定排序；改变后回第 1 页。
- 分页：每页 12 项；上一页、页码、下一页、总数。
- 重置：清空关键词、标签、日期，恢复默认排序和第 1 页。
- 返回恢复：从详情返回或关闭照片弹窗后保留查询、排序和页码。
- 空状态：无匹配显示“没有找到匹配内容”和重置；原始空内容显示“暂无文章/相册/照片”。

#### 文章

- 文章专栏列表：搜索名称/简介；标签筛选；按创建日期；排序最近更新/文章数；每页 12。
- 专栏内文章列表：只查当前专栏；搜索标题/摘要；标签；按发布日期；排序最新/最早；每页 12。
- 文章详情：面包屑、标题、专栏、发布时间、更新时间、标签、正文、目录。
- 目录：h2/h3 生成；点击定位并高亮；滚动同步；PC 侧栏，窄屏顶部；无标题隐藏。
- 阅读余量：正文后保留至少一屏，承载“本文完、上一篇/下一篇、返回顶部”；短文章不强制。
- 代码块：左上语言标签，右上复制按钮；复制完整原始代码；成功/失败提示；非安全上下文兜底；触屏常显。
- 公式：KaTeX；过长内部滚动；失败显示原文和重试。
- Mermaid：按宽度渲染；过密可横向查看；失败显示原文。
- 图片：无元数据衍生图；保持比例；替代文本和图注；失败不影响正文。

#### 摄影

- 摄影专栏列表：搜索名称/简介；题材枚举；标签；按创建日期；排序最近更新/相册数；每页 12。
- 相册列表：只查当前摄影专栏；搜索标题/简介/位置；标签；按相册最新更新时间；排序最新/照片数；每页 12。
- 空相册不公开；后台仍可见。
- 相册瀑布流：按宽度分栏；保持原始比例；横竖混排；按尺寸预留位置；每页 12；键盘顺序一致；单图失败可单独重试。
- 照片弹窗：
  - 固定尺寸查看区，不随照片比例变化。
  - 初始适应区域，完整显示不裁切。
  - 滚轮以光标为中心缩放 100%–600%；放大后可拖动。
  - 双击复位；不显示百分比，不提供加减/复位按钮。
  - 切换照片或重新打开时缩放和位移复位。
  - 上一张/下一张固定在图片区左右两侧垂直居中；进入图片区显示，移出隐藏；首尾隐藏。
  - 触屏支持双指缩放、单指拖动；切换按钮常显；未缩放时可横向滑动切换。
  - 方向键切换时焦点留在弹窗内，不聚焦关闭按钮。
  - 信息区：标题、描述、拍摄时间、相机、镜头、焦距、光圈、快门、ISO、可选位置；缺失隐藏；不展示原始 EXIF/GPS/编辑身份。
  - 关闭：按钮、Esc、点击遮罩；关闭后恢复查询和原照片焦点。

### 1.8 编辑工作区

- 只显示本人内容；支持搜索、公开状态、审核状态、标签筛选；每页 12。
- 同时显示“公开状态 + 审核状态”，例如“已发布 + 待审核”。
- 已公开但因上级隐藏时显示原因。
- 操作：新增、编辑、预览、提交审核、撤回、下线、移入回收站、恢复。
- 文章专栏：名称、简介、封面必填；标签可选。
- 文章：标题、所属本人专栏、摘要、不晚于当天的发布时间、至少一个有效正文块必填。
- 摄影专栏：名称、简介、封面、题材必填。
- 相册：所属本人摄影专栏、标题、简介、封面必填；标签、位置可选。
- 照片：所属本人相册、有效原图、可用衍生图、不晚于当天的拍摄时间必填；标题、描述、标签、位置、元数据可选。
- 草稿可暂缺；提交审核前校验。
- 预览区分“当前公开版”和“待提交工作版”。
- 待审可撤回；驳回保留内容和理由；离开未保存页面需确认。
- 照片上传：单次最多 20 张；格式和大小按规则校验；分片上传；逐张状态；失败可重试；上传完成不等于公开。
- 下线：本人已公开内容可立即下线；重新上线需审批。
- 回收站：本人内容可移入；恢复为已下线；永久删除仅管理员。
- 含下级的专栏/相册不能整体移入回收站，需先处理下级。

### 1.9 管理员后台

- 全站内容管理：按所有者、公开状态、审核状态、标签、时间筛选；新增/编辑/预览/直接发布/下线/回收站/恢复。
- 审批中心：按提交时间排列；按类型、编辑、日期筛选；显示提交人、内容、首次/修改、时间、当前公开状态。
- 审批必须完整预览：正文按公开端渲染，图片、代码、公式、Mermaid 实际显示；照片显示大图、描述、元数据、位置。
- 修改类审批提供当前公开版与提交版差异；图片替换对比衍生图。
- 预览失败不能通过，只能驳回或稍后处理。
- 通过前再次校验版本、归属、上级状态、衍生图可用性；通过后记录审核人和版本。
- 驳回理由必填；旧公开版继续展示；工作版本和理由保留。
- 同一版本只能产生一次有效审批；重复点击不重复发布。
- 首页推荐：分别配置 `N₁`、`N₂`；选择并排序；预览手动 + 补位结果；保存/清空/恢复全自动。
- 账号权限：创建普通账号、授予/撤销编辑、重置密码、禁用/启用；管理员账号只能服务器命令添加。
- 回收站：恢复校验上级；恢复后统一“已下线”；永久删除二次确认，清除内容、版本、原图、衍生图、缓存、云端副本和处理临时文件；失败保留记录可重试。
- 系统管理：标签词库查看、重命名、合并、停用；只读系统信息与操作审计；上传限制、衍生图策略、水印参数和会话安全仅显示部署值，不在后台修改。
- 后台设备分级：高风险操作仅 PC；手机端可查看、草稿、提交、撤回、下线/恢复、移入/恢复回收站、首次发布审批通过（单条）、审批驳回、推荐排序。
- 后台交互：固定左侧导航（内容/运营/管理）、待审和回收站徽章、状态标签、二次确认、失败重试、操作日志。

### 1.10 共用业务规则

**上传限制：**

| 用途 | 格式 | 单张大小 | 单次数量 |
|---|---|---|---|
| 文章图片 | JPG、PNG、WebP、HEIC/HEIF | < 5 MB | ≤ 20 张 |
| 摄影照片 | JPG、PNG、HEIC/HEIF | < 50 MB | ≤ 20 张 |

- 按实际文件格式校验，不只看扩展名。
- 超限文件单独失败，其他合规文件继续。
- 分片上传，失败只重试失败分片；全部分片完成才形成有效原图。
- 衍生图失败保留原图，可重新处理，不要求重传全部。

**媒体安全：**

- 原图私有；访客无原图地址、无下载按钮。
- 编辑只看本人原图；管理员可看全部。
- 公开端只使用压缩衍生图。
- 衍生图剥离 EXIF/GPS/XMP/IPTC/MakerNotes。
- 展示参数来自上传时读取的数据库字段，不由图片携带。
- HEIC/HEIF 必须生成浏览器可看的衍生图。
- 软删除保留原图和衍生图；永久删除按回收站规则清除。

**位置：**

- 国家、省/州、城市、区/县、镇/村、街道、具体地点均可选填。
- 可只填部分层级；按顺序展示已填内容，跳过空层级。
- 全空显示“未记录”；原始 GPS 不作为公开字段。

**失败处理：**

- 提交失败保留工作版本；审批失败保留公开版和待审版。
- 撤权后新操作立即拒绝；下线/回收站影响下级和推荐，需明确提示。
- 上传部分失败保留成功项；未保存离开提示。

## 2. 技术方案

### 2.1 总体架构

```text
浏览器 / 小程序 / App
        │
        ├─ 静态页面 ── CDN（后期）── OSS 衍生图
        │
        └─ API 请求 ── Caddy ── Go API (/api/v1)
                                  ├─ PostgreSQL
                                  ├─ River / SKIP LOCKED 任务
                                  └─ 阿里云 FC / OSS

原图 ── 私有 OSS ── FC 清洗 ── 公开衍生图 ── CDN
```

运行时：

- Caddy：HTTPS、静态文件、反向代理。
- Go API：业务接口。
- PostgreSQL：唯一主数据库。
- 可选 worker：与 API 同代码库，首版可不部署。
- 无 Node 常驻、无 Redis、无 MinIO、无独立搜索服务。

### 2.2 技术栈

| 层 | 选择 |
|---|---|
| 后端 | Go 1.23+、chi/echo、pgx + sqlc、goose |
| 数据库 | PostgreSQL 16 |
| API 契约 | OpenAPI 3.1 + oapi-codegen |
| 认证 | JWT access + refresh、argon2id |
| 队列 | River 或 PostgreSQL `SKIP LOCKED` |
| 日志 | log/slog |
| 公开站 | Astro + React islands + Tailwind |
| 管理后台 | React + Vite + Ant Design + TanStack Query + React Hook Form + Zod |
| 内容渲染 | goldmark + Chroma + bluemonday；KaTeX/Mermaid 客户端增强 |
| 图片 | 阿里云 OSS + 阿里云 FC |
| 搜索 | PostgreSQL + pg_jieba/zhparser + pg_trgm |
| 通知 | 站内通知表 + `Notifier` 接口；首版不做邮件 |
| 统计 | GoAccess（当前）/ Umami（4G 后） |
| 部署 | Docker Compose + Caddy |
| CI | GitHub Actions / Gitee Go |
| 监控 | Sentry + 外部 uptime + 日志轮转 |

### 2.3 前端

**公开站：Astro 静态生成。**

- 文章、相册、首页构建成 HTML，Caddy 直接返回。
- 筛选、搜索、图片查看器用 React island。
- 构建触发：后台发布 → CI webhook → Astro 拉 API → 静态产物 → 上传/发布。
- 发布延迟目标：正常 5 分钟内，最差 10 分钟；CI 将构建状态写入 `system_info`，后台只读展示，失败时旧版继续服务。
- SEO：canonical、sitemap、robots、Open Graph、结构化数据。

**管理后台：独立 React SPA。**

- Ant Design 负责表格、表单、上传、日期、弹窗、审批。
- 与公开站分开构建，后台代码不进入公开包。
- 权限仍由 API 校验，前端隐藏只是体验。

### 2.4 后端模块化单体

```text
services/api/
  cmd/
    api/main.go
    worker/main.go
  internal/
    platform/
    modules/
      auth/
      articles/
      photography/
      media/
      taxonomy/
      review/
      recommendation/
      audit/
    migrations/
  api/openapi.yaml
```

模块契约：

```go
type Module interface {
    ID() string
    Routes() []Route
    Permissions() []Permission
    Migrations() []Migration
    Menus() []MenuItem
    Events() []Event
    Enabled(ctx context.Context) bool
}
```

规则：

- 模块只访问自己的表；跨模块通过 service 或事件。
- `Enabled=false` 不挂路由、不进菜单、不跑任务。
- 下线不删数据；卸载必须 migration + 备份。
- 新增功能 = 新增模块目录。
- `GET /api/v1/capabilities` 返回启用模块、菜单、权限；前端据此生成导航。
- 不做微服务、不做 Go `.so` 热插拔；编译期模块 + 运行时开关即可。

### 2.5 API 约定

- 统一前缀 `/api/v1`；后台 `/api/v1/admin`。
- 分页 `page` + `pageSize`，默认 12；排序带稳定次级字段。
- 错误格式：`code`、`message`、`details`、`requestId`。
- 写操作支持 `Idempotency-Key`；审批、发布、删除必须幂等。
- 列表和详情支持 `ETag` / `If-None-Match`。
- OpenAPI 是唯一契约来源，前端类型由契约生成。
- access token 短期；refresh token 轮换；Web 用 HttpOnly/Secure/SameSite Cookie。
- 对象级权限在 API 校验：归属、公开状态、审核状态、禁用状态。
- 高风险操作要求二次确认/二次验证；不能只靠 User-Agent 判断 PC。

核心表：

article_columns
articles
photo_columns

后期表：

```text
comments

```

**对象与版本化映射：**

| PRD 对象 | 数据表 | 版本化方式 |
|---|---|---|
| 文章专栏 | `article_columns` | `content_versions`（`entity_type='article_column'`）+ `published_version_id` |
| 文章 | `articles` | `content_versions`（`entity_type='article'`）+ `published_version_id` |
| 摄影专栏 | `photo_columns` | `content_versions`（`entity_type='photo_column'`）+ `published_version_id` |
| 相册 | `albums` | `content_versions`（`entity_type='album'`）+ `published_version_id` |
| 照片 | `photos` + `media_assets` | `content_versions`（`entity_type='photo'`）保存文字版本；图像由 `media_assets` 记录并随版本快照引用 |
| 首页推荐 | `recommendations` | 不版本化，保存即生效 |
| 审核记录 | `reviews` | 指向 `entity_type + entity_id + version_id` |
| 标签词库 | `tags` / `content_tags` | 标签词库本身不版本化，重命名/合并/停用立即生效；内容与标签的关联随版本快照保存，审批时移除只影响提交版本 |

关键设计：

- `article_columns.published_version_id`、`photo_columns.published_version_id`、`articles.published_version_id`、`albums.published_version_id`、`photos.published_version_id` 指向已通过审批的版本。
- `content_versions` 保存实体快照、提交人、审核状态和渲染快照；文章额外保存 Markdown 源、AST 和 HTML。
- 文章专栏、摄影专栏、文章、相册、照片都遵循同一版本规则：编辑提交后公开版保持不变，管理员审批通过后才替换公开版本。
- 审批针对具体版本；预览和发布使用同一份渲染快照。
- 标签用 `scope` 隔离，唯一约束 `(scope, name)`；允许同名，不跨作用域合并。
- 照片位置、拍摄时间等需筛选字段单独建列；其余元数据放 JSONB。
- 主键用 UUIDv7 或 ULID；分页稳定。
- 删除走软删除 + 回收站；永久删除异步清理对象存储，数据库备份中的历史副本随 30 天轮转失效。
- `system_info` 由部署脚本或 CI 写入版本、构建状态、存储用量和任务状态，后台只读展示。

### 2.7 媒体管线

```text
客户端 → API 申请预签名
       → 直传私有 OSS（分片）
       → API 校验文件头/大小/归属
       → 写 media_assets
       → FC 触发：校验、提取 EXIF、纠正方向、剥离元数据、生成清洗 master/BlurHash
       → OSS 图片处理从 master 生成展示变体
       → CDN 缓存公开变体
```

**EXIF 白名单：**

- 设备机型、镜头、焦距/等效焦距、光圈、快门、ISO。
- 原始拍摄时间 + 时区、曝光补偿、白平衡。
- 方向（只用于纠正）、原图尺寸。
- 不读取、不保留 GPS、测光、闪光灯等；位置用独立结构化字段。
- 当前展示变体由 OSS 图片处理参数生成；迁移腾讯云前预生成固定变体 key，只改 `assetUrl`/`AssetResolver` 实现。

**衍生图：**

| 用途 | 长边 | 格式 |
|---|---|---|
| 瀑布流缩略图 | 480 / 960 | WebP，质量 75–80 |
| 相册网格 | 960 | WebP |
| 详情查看 | 1440 / 2048 | WebP，质量 80 |
| 大屏查看 | 2560 | WebP，质量 80–85 |

- 详情和放大最多 2560，不提供原图。
- 统一转 sRGB，剥离 EXIF/XMP/IPTC/MakerNotes；先纠正方向再剥离。
- 文件名用内容哈希，便于缓存。
- 水印：右下角小 Logo，宽度 5–7%，最小 24px、最大 120px，透明度 55–70%；480 用简化版；水印资源带版本号。

**CDN 预留：**

```go
type AssetResolver interface {
    PublicURL(key, variant string) string
    SignedURL(key string, ttl time.Duration) (string, error)
    PresignPut(key, contentType string) (string, map[string]string, error)
    Purge(key string) error
}
```

- 数据库只存 `storage_key`，不存 URL。
- 内容里只写 `media://<id>`，渲染时解析。
- 前端统一 `assetUrl(key, variant)`；禁止写死域名。
- 当前 `ASSET_BASE_URL` 指向 OSS；接 CDN 后改成 `https://cdn.twilightlog.com`，内容和数据库不动。

### 2.8 搜索

- PostgreSQL + `pg_jieba`/`zhparser` + `pg_trgm`。
- 索引字段加权：标题 A、摘要/标签 B、正文 C。
- 正文索引前去掉 Markdown 标记和代码块。
- 自定义词典补人名、地名、摄影术语、技术名词。
- GIN 索引 + `ts_rank`；效果不够再评估 Meilisearch，不首版引入。
- 搜索接口 `/api/v1/search`；公开站客户端调用，结果不进入静态 HTML。

### 2.11 部署与服务器

当前 2C2G / 40G：

```text
系统            250–350MB
Caddy            30–50MB
Go API           50–100MB
PostgreSQL      300–450MB
余量            700MB–1GB
```

要点：

- 不在服务器构建前端；构建放 CI。
- 图片不落本地磁盘。
- PostgreSQL 调低 `shared_buffers`、`max_connections`、`work_mem`。
- 加 2G swap 防 OOM。
- Docker Compose 服务：`caddy`、`api`、`postgres`，`worker` 可选。
- 不部署 Redis、MinIO、Node 常驻、独立搜索。

续费建议：

| 档位 | 配置 | 适用 |
|---|---|---|
| 最低 | 2C4G / 80G ESSD / 3–5M 或流量包 | Go + PG + 静态站 |
| 推荐 | 4C8G / 100G ESSD / 5–10M 或流量包 | 后续任务/统计/搜索余量 |
| 不建议 | 2C2G / 40G / 3M | 只够当前 |

优先加内存；CPU 4 核给未来任务和数据库余量。图片外置后，3–5M 带宽足够 API；不要为峰值数字牺牲内存。

### 2.12 域名、CDN 与迁移

| 域名 | 用途 |
|---|---|
| `www.twilightlog.com` | 公开站 canonical |
| `twilightlog.com` | 301 到 www |
| `api.twilightlog.com` | Go API |
| `admin.twilightlog.com` | 管理后台 |
| `cdn.twilightlog.com` | 图片/静态资源 |

- Cookie `Domain=.twilightlog.com`；CORS 只允许 www/admin。
- 证书覆盖子域；Caddy 自动 HTTPS。
- 当前 CDN 不买；`ASSET_BASE_URL` 先指 OSS，后期改 CDN。
- 迁腾讯云：资源 key 不变、`cdn` CNAME 切换、`api` DNS 切换、数据库备份恢复；域名不变。
- 国内跨云需处理备案接入变更。

### 2.13 多端

- 现在：Web 公开站 + 管理后台 + API。
- 下一步：PWA。
- 小程序：Taro（React）接同一 API；后台和高危操作不进小程序。
- Android：先 PWA；确需上架再评估 React Native。
- 只共享 API 契约、类型、设计 token，不共享页面组件。
- 小程序对公式、Mermaid、长代码降级或 `web-view`。

### 2.14 安全基线

- 所有后台地址和对象级操作服务端校验；越权与不存在响应一致。
- 编辑只能访问本人内容；访客只能访问公开衍生图。
- 上传按文件头校验；限制大小、数量、类型；分片幂等。
- 原图私有；衍生图剥离元数据；不提供下载。
- 登录限速、失败锁定、会话失效；禁用账号即时拒绝。
- 高风险操作二次确认 + 审计；仅 PC 入口。
- 密钥只放环境变量；生产数据库不允许 AI 直接执行 SQL。
- 永久删除清除对象存储、缓存和副本；失败保留记录可重试。

### 2.15 AI 开发约束

1. TypeScript 严格模式；Go `go vet`、`staticcheck`。
2. 接口边界用 OpenAPI/validator 校验。
3. 数据库只允许 migration 改表。
4. 每个功能通过类型检查、lint、单元测试、构建。
5. 关键链路 Playwright 冒烟：登录、发布、审批、上传、照片弹窗。
6. 一次只做一个模块，完成提交 Git，便于回滚。
7. 权限只在 API 校验；前端隐藏不算安全。
8. 密钥、数据库密码、OSS AK 只放环境变量。
9. AI 生成的部署脚本必须人工核对后再执行。
10. 不允许 AI 直接操作生产数据库。

## 3. 开发流程

> 每个阶段都按“目标 → 任务 → 产出 → 验收”执行。上一阶段验收不通过，不进入下一阶段。

### 阶段 0 · 账号与基础设施准备

**目标：** 把外部依赖准备好，避免开发中途被域名、存储、服务器卡住。

**任务：**

1. 确认阿里云账号、实名认证、备案信息。
2. 创建 OSS Bucket：
   - `twilightlog-private`：原图，私有读。
   - `twilightlog-public`：衍生图，公共读或 CDN 回源。
3. 创建阿里云函数计算 FC 服务，预留图片处理函数。
4. 配置域名解析：`www`、`api`、`admin`、`cdn`。
5. 服务器安装 Docker、Docker Compose、Git；配置 SSH 密钥、防火墙。
6. 创建 Git 仓库；确定分支策略（`main` 保护，功能分支）。
7. 本地安装 Go、Node、pnpm、Docker、Playwright。
8. 建 `.env.example`，列出数据库、JWT、OSS、FC、域名配置。

**产出：**

- OSS 两个 Bucket、FC 服务、DNS 记录、服务器可 SSH、仓库可推送。
- `.env.example` 和基础 README。

**验收：**

- 能通过 OSS SDK 上传/读取测试文件。
- 能用签名 URL 访问私有原图，公开 Bucket 可直接访问衍生图。
- `www` 能打开占位页，`api` 能返回健康检查。

### 阶段 1 · 仓库、骨架与部署底座

**目标：** 建立可运行、可部署、可测试的最小骨架。

**任务：**

1. 初始化目录：

```text
apps/web
apps/admin
services/api
packages/api-client
packages/design-tokens
infra/caddy
infra/compose
```

2. Go API：
   - `GET /healthz`、`GET /readyz`。
   - 配置加载、slog、请求 ID、统一错误格式。
   - 连接 PostgreSQL，接入 goose migration。
3. 数据库：创建 `schema_migrations` 和最小 `users` 表。
4. Caddy：反向代理 `/api/*`，托管占位静态页。
5. Docker Compose：`caddy`、`api`、`postgres`。
6. CI：Go 测试、前端 typecheck/build、Docker 镜像构建。
7. OpenAPI 骨架：`/api/v1`、认证、错误结构。

**产出：**

- 本地 `docker compose up` 可启动。
- 健康检查、迁移、占位页可用。
- CI 能跑通。

**验收：**

- `curl /healthz` 返回 200。
- 迁移可重复执行，不破坏数据。
- CI 在 PR 上通过。
- 服务器能拉取镜像并启动。

### 阶段 2 · 认证、角色与路由防护

**目标：** 先建立“谁能做什么”的边界，后续所有接口都依赖它。

**任务：**

1. 用户、角色、权限表；管理员账号通过 CLI 创建，不开放后台新增管理员。
2. 登录、刷新、退出、`/auth/me`；argon2id 密码；JWT access + refresh。
3. 编辑/管理员角色；禁用账号；撤权逻辑。
4. API 中间件：认证、角色、对象级权限、请求 ID、限速。
5. 后台路由守卫：未登录跳登录；无权限统一“无权访问”；不返回内容数据。
6. 审计日志：登录、授权、撤权、禁用、审批、发布、删除。
7. 前端登录页；登录后按角色进入工作区或后台。

**产出：**

- 可登录/退出/刷新。
- 管理员可创建编辑、授权、撤权、禁用。
- 未授权访问统一拒绝。

**验收：**

- 编辑不能访问 `/admin/*`。
- 编辑不能通过改 URL 访问他人内容。
- 撤权后下一次请求立即失败。
- 审计日志有记录。

### 阶段 3 · 媒体上传与图片管线

**目标：** 打通“上传 → 清洗 → 衍生图 → 公开访问”的完整链路。

**任务：**

1. 预签名上传接口；分片上传/完成/失败重试。
2. 文件头、大小、格式、数量校验；单次最多 20 张。
3. `media_assets` 表：key、变体、宽高、BlurHash、状态、所有者。
4. FC 函数：
   - 读取私有原图。
   - 提取 EXIF 白名单。
   - 纠正方向，转 sRGB。
   - 剥离 EXIF/GPS/XMP/IPTC/MakerNotes。
   - 生成清洗 master、BlurHash。
5. OSS 图片处理：w480/w960/w1440/2048/2560、WebP。
6. 水印：右下角 Logo，按尺寸自适应；资源版本化。
7. `AssetResolver`：`PublicURL`、`SignedURL`、`PresignPut`、`Purge`；当前 `Purge` 空实现。
8. 本地开发存储适配器；生产只用 OSS。
9. 媒体状态：上传中、处理中、可用、失败；失败可重试。

**产出：**

- 上传接口、FC 处理、衍生图、公开 URL。
- 数据库记录元数据和状态。

**验收：**

- 上传 JPG/PNG/HEIC，能生成公开 WebP。
- 公开图无 EXIF/GPS；原图私有。
- 水印在右下角，不遮挡主体。
- 失败分片可重试，不重复创建。
- 详情图最大 2560，无原图入口。

### 阶段 4 · 内容模型、只读 API 与搜索

**目标：** 先让公开站有稳定数据可读，不依赖后台 UI。

**任务：**

1. 内容表：专栏、文章、摄影专栏、相册、照片、标签、版本。
2. 版本与状态：公开版/工作版、草稿/已发布/已下线/回收站、待审/驳回。
3. 公开可见条件与上级联动。
4. 只读 API：首页推荐、文章专栏/列表/详情、摄影专栏/相册/照片、搜索。
5. 列表参数：搜索、标签 AND、日期、排序、分页 12；ETag。
6. 标签作用域隔离；题材枚举。
7. 搜索：pg_jieba/zhparser 索引、权重、去 Markdown/代码块。
8. 种子数据：至少 3 个文章专栏、10 篇文章、3 个摄影专栏、6 个相册、30 张照片。
9. API 契约测试。

**产出：**

- 公开只读 API 完整可用。
- 种子数据可重复导入。
- OpenAPI 文档可浏览。

**验收：**

- 列表筛选/排序/分页正确。
- 标签 AND 正确，文章/摄影标签不混。
- 无权/不存在响应一致。
- 搜索能命中中文标题、摘要、正文。

### 阶段 5 · 公开站静态 MVP

**目标：** 用种子数据做出可浏览的公开站，先验证体验。

**任务：**

1. Astro 项目、布局、导航、页脚、主题切换。
2. 首页：介绍、入口、推荐区、补位逻辑、入场动效。
3. 文章：专栏列表、文章列表、详情、目录、代码块复制、公式、Mermaid、阅读余量。
4. 摄影：专栏列表、相册列表、瀑布流、照片弹窗。
5. 查询栏：搜索、标签、日期、排序、分页、重置、返回恢复。
6. 响应式：PC/平板/手机；照片瀑布流分栏。
7. SEO：canonical、title/description、Open Graph、sitemap、robots。
8. 构建脚本：从 API 拉数据，生成静态文件。
9. 构建状态页/通知：发布后显示构建中/成功/失败。

**产出：**

- 可本地预览的静态公开站。
- 构建产物可部署到 Caddy/OSS。

**验收：**

- 文章代码块可复制，语言标签正确。
- 目录点击可定位，末尾标题不被遮挡。

### 阶段 6 · 管理后台与编辑工作区

**目标：** 让内容真正可生产、可审批、可运维。

**任务：**

**产出：**

- 完整后台和编辑工作区。

**验收：**

## 4. 验收标准

### 4.1 全局 Definition of Done

每个功能必须满足：

- 需求与 PRD 一致；边界和异常有处理。
- API 契约更新；前端类型生成。
- 数据库 migration 可重复执行。
- 类型检查、lint、单元测试、构建通过。
- 关键路径有 Playwright 或集成测试。
- 权限在 API 校验；无越权。
- 响应式、键盘、焦点、主题可用。
- 无 console 错误；无敏感信息进日志。

### 4.2 功能验收清单

- 首页推荐顺序、补位、N=0、失效补位正确。
- 五类列表搜索/标签 AND/日期/排序/分页/重置/返回恢复正确。
- 文章代码块复制、语言标签、目录定位、阅读余量、公式/Mermaid 正常。
- 照片瀑布流保持比例；弹窗固定尺寸、缩放、拖动、复位、上下张、焦点正确。
- 编辑只能管理本人内容；提交/撤回/驳回/重新提交状态正确。
- 审批完整预览；预览失败不能通过；驳回理由必填。
- 公开版与工作版隔离；审批期间旧版可见。
- 首页推荐、账号权限、回收站、永久删除、通知、审计闭环。
- 深浅色持久化；手机/平板/PC 无页面级横向滚动。

### 4.3 安全验收

- 未登录/访客访问后台或编辑地址被拒绝。
- 编辑改 URL/参数不能访问他人或非公开内容。
- 原图地址不可公开访问；衍生图无 EXIF/GPS。
- 上传按文件头校验；超限/非法格式被拒绝。
- 永久删除清除原图、衍生图、缓存、云端副本和处理临时文件。
- 高风险操作仅 PC，且 API 校验。
- 密码、JWT、OSS AK 不进代码库。
- 登录限速、失败处理、禁用账号生效。

### 4.4 性能、SEO、多端

- 公开站静态文件由 Caddy/CDN 返回；API 不参与页面渲染。
- 图片使用衍生图、`srcset`、懒加载、尺寸占位。
- 首页/列表/详情首屏可接受；无布局跳动。
- canonical、301、sitemap、robots、Open Graph 正确。
- 手机触屏可完成所有公开端操作；不依赖 hover。
- 深色模式文字、代码、公式、Mermaid、弹窗可读。

## 5. 运维

### 5.1 备份

- 每日 `pg_dump` 到 OSS，保留 30 天。
- 对象存储开启版本控制或生命周期。
- 备份定期演练恢复；没有恢复演练的备份不算备份。
- 日志轮转，避免 40G 磁盘占满。

### 5.2 监控

- Sentry：前后端异常。
- 外部 uptime：首页、API 健康检查。
- 日志：Caddy、API、FC、PostgreSQL。
- 磁盘、内存、备份失败、证书到期告警。

### 5.3 发布与回滚

- 镜像打版本 tag；数据库 migration 向后兼容。
- 发布前备份；发布后 smoke。
- 静态站保留上一版产物；失败回滚。
- CDN 接入后发布需刷新缓存。

### 5.4 换服务器 / 迁腾讯云

1. 新服务器启动同一 Compose。
2. 恢复 PostgreSQL。
3. `api` DNS 或 CDN 回源指向新 IP。
4. OSS 同步 COS；`cdn` CNAME 切换。
5. 清理 CDN 缓存。
6. 验证登录、列表、详情、上传、审批。
7. 旧服务器观察后下线。
8. 国内跨云提前办理备案接入变更。

### 5.5 成本控制

- 图片是主要流量；控制衍生图数量和尺寸。
- CDN 缓存命中率优先；避免频繁刷新全站。
- OSS 生命周期清理临时文件。
- 2C2G 不跑构建、不跑图片处理。
- 续费优先内存，其次磁盘；带宽按 API 需求即可。

## 6. 风险与待确认

### 6.1 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| Go CRUD 开发比 TS 慢 | 迭代速度 | sqlc/OpenAPI 减少重复；AI 辅助 |
| 静态发布有延迟 | 新内容不能秒级可见 | 接受 5–10 分钟；必要时详情页 SSR 兜底 |
| 两套前端 | 维护成本 | 共用类型和设计 token；后台独立 |
| 2C2G 内存紧 | OOM | swap、PG 调参、构建放 CI |
| 依赖 OSS/FC | 成本与网络 | AssetResolver 抽象；本地适配器 |
| CDN 后接 | 迁移风险 | 域名稳定、URL 统一生成、缓存可清 |
| 备案/跨云 | 上线/迁移时间 | 提前办理；同厂商优先 |
| 小程序渲染限制 | 内容不一致 | 简化渲染或 web-view |

### 6.2 待确认

1. 首页推荐默认值和上限（PRD `TBD-02`）。
2. TwilightLog 一笔成型 Logo 设计与定稿。
3. 清洗 master 最大长边和是否长期归档原图。
4. 评论启动时的验证码阈值和长度上限。

> 已定稿、不再列为待确认：公开衍生图压缩策略（技术 8.7）、水印尺寸与透明度（技术 8.8）、4G 后接入 Umami（技术 13）。

### 6.3 后续功能

- CDN 接入。
